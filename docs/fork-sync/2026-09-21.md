## Consumer boundaries

Postgen's `pg:` actions and HumorBank's generic `rh:` / `rv:` review helper remain
fork contracts. HumorBank v2 also installs its separate `hb:` feedback handler at
image-build time. Its provider `extra_body` patch must follow the gateway's current
module layout so LiteLLM/Muse session metadata survives every turn.

The read-only Postgen audit found existing limitations outside this sync: the
consumer's receipt ledger does not persist every carousel binding once delivery is
confirmed; slide revision selection is not durably recorded; the final-response
album path has weaker partial-delivery handling than standalone `send_message`.
Preserving the existing fork does not establish that these separate consumer
problems are fixed.

## Plugin readiness

This base includes upstream PR [#117451](https://github.com/NousResearch/hermes-agent/pull/117451),
the generic external-process provider support. The vendor implementation remains
in the standalone [Claude Subscription DirectSDK plugin](https://github.com/NousResearch/hermes-plugin-claude-subscription-directsdk).

Adding it to HumorBank later requires a pinned plugin, Claude Code in the operator
image, runtime authentication accessible to the container user, and an explicit
model/config change in the existing profile. Editing the profile template alone
does not migrate an already-created profile. No subscription credentials, active
provider selection, auxiliary routes, schedules or deployed images are changed here.
